# NAT端口映射场景配置总结

**更新时间**: 2025-11-27 18:30
**场景**: 服务器192.168.50.48在私网，通过NAT公网IP 112.48.19.183提供服务

---

## ⚠️ 关键问题

### 你的端口映射配置
```
112.48.19.183:11025 → 192.168.50.48:500   (IKE)
112.48.19.183:11026 → 192.168.50.48:4500  (NAT-T)
112.48.19.183:11027 → 192.168.50.48:50    (ESP)
112.48.19.183:11028 → 192.168.50.48:47    (GRE)
```

### ❌ 主要问题

1. **使用了非标准端口** (11025/11026/11027/11028)
   - Racoon只能监听标准端口500/4500
   - 路由器也期望连接到标准端口500/4500
   - **无法通过配置Racoon监听11025端口**

2. **ESP(50)和GRE(47)是IP协议号，不是TCP/UDP端口**
   - 不能简单做端口映射
   - 需要NAT网关的**协议转发**功能

---

## ✅ 正确解决方案

### 方案1: 标准端口映射（推荐）

**在NAT网关上修改端口映射**:

```
外部访问              →  内部服务器
------------------------------------------
112.48.19.183:500     →  192.168.50.48:500
112.48.19.183:4500    →  192.168.50.48:4500
```

**协议转发**（如果NAT支持）:
```
IP协议 50 (ESP)  →  192.168.50.48
IP协议 47 (GRE)  →  192.168.50.48
```

### 方案2: NAT-T Force模式（如果NAT不支持协议转发）

**端口映射**:
```
112.48.19.183:500     →  192.168.50.48:500
112.48.19.183:4500    →  192.168.50.48:4500
```

**服务器配置** - 强制使用NAT-T:
- 所有IPSec流量通过UDP 4500封装
- 不依赖ESP协议50
- GRE通过IPSec隧道传输

## ❌ 常见错误

### 错误1: 连接超时

**原因**: 端口映射使用了11025而不是500

**解决**:
```
在NAT网关上修改:
11025 → 改为 500
11026 → 改为 4500
```

### 错误2: Phase 1失败 - "no response"

**原因**: 防火墙或NAT配置问题

**检查**:
```bash
# 在服务器上抓包
sudo tcpdump -i any -n port 500 or port 4500

# 应该能看到路由器发来的IKE请求
```

### 错误3: Phase 2失败 - ESP问题

**原因**: ESP协议被阻止

**解决**: 启用NAT-T force模式，所有流量走UDP 4500

### 错误4: IPSec成功但GRE不通

**原因**: GRE协议转发未配置

**解决**:
1. 使用NAT-T force模式（GRE会封装在UDP 4500中）
2. 或在NAT网关配置GRE协议转发

## 💡 为什么必须用标准端口？

### Racoon的限制

```c
// Racoon源码中硬编码的端口
#define PORT_ISAKMP 500
#define PORT_ISAKMP_NATT 4500

// 无法通过配置文件修改
```

### IPSec协议标准

- RFC 2408定义IKE使用UDP 500
- RFC 3947定义NAT-T使用UDP 4500
- 路由器端也遵循这些标准

### 结论

**无法通过配置让Racoon监听11025端口，必须使用标准端口500/4500**
