# DMVPN NAT端口映射配置指南

**日期**: 2025-11-27
**场景**: 服务器在私网，通过NAT端口映射提供公网访问

---

## 🌐 网络拓扑

```
路由器(公网/4G)
     ↓
  Internet
     ↓
NAT网关 (112.48.19.183)
     ↓ 端口映射
DMVPN服务器 (192.168.50.48) - 私网
```

## 📋 端口映射配置

| 协议 | 标准端口 | 映射到公网 | 用途 |
|------|---------|-----------|------|
| UDP  | 500     | 11025     | IKE协商 |
| UDP  | 4500    | 11026     | NAT-T (IPSec over UDP) |
| ESP  | 50      | 11027     | IPSec数据加密 |
| GRE  | 47      | 11028     | GRE隧道 |

**公网访问地址**: `112.48.19.183`

---

## ⚠️ 关键问题

### 问题1: 非标准端口导致协议不兼容

**原因**:
- IKE协议默认期望 UDP 500，不是 11025
- NAT-T默认期望 UDP 4500，不是 11026
- ESP (50) 和 GRE (47) 是**IP协议号**，不是端口号，无法简单映射

### 问题2: Racoon无法监听非标准端口

**Racoon的限制**:
- Racoon只能监听标准端口 500/4500
- 不支持自定义端口配置

### 问题3: ESP和GRE的协议映射

**IP协议 vs TCP/UDP端口**:
- ESP (协议50) 和 GRE (协议47) 不是基于端口的
- 需要NAT网关支持**协议转发**，不是简单的端口映射

---

## ✅ 解决方案

### 方案A: 修改NAT映射为标准端口（推荐）

**调整端口映射配置**:

```
公网IP 112.48.19.183:500  → 192.168.50.48:500   (IKE)
公网IP 112.48.19.183:4500 → 192.168.50.48:4500  (NAT-T)
```

**协议转发**:
```
IP协议 50 (ESP)  → 192.168.50.48
IP协议 47 (GRE)  → 192.168.50.48
```

**路由器配置**:
```
Hub地址: 112.48.19.183
Hub端口: 500 (默认)
```

### 方案B: 使用NAT-T模式（备选）

如果NAT网关不支持ESP/GRE协议转发，**完全依赖NAT-T**：

**端口映射**:
```
公网IP 112.48.19.183:500  → 192.168.50.48:500
公网IP 112.48.19.183:4500 → 192.168.50.48:4500
```

**服务器Racoon配置** `/etc/racoon/racoon.conf`:
```conf
log notify;
path include "/etc/racoon/";
path pre_shared_key "/etc/racoon/psk.txt";

# 强制NAT-T模式
remote anonymous {
        exchange_mode main;
        lifetime time 10800 seconds;
        my_identifier address;
        dpd_delay 30;
        dpd_retry 3;
        dpd_maxfail 6;

        # 关键配置
        nat_traversal force;  # 强制使用NAT-T

        proposal {
                encryption_algorithm aes256;
                hash_algorithm sha256;
                dh_group modp3072;
                authentication_method pre_shared_key;
        }
}

sainfo anonymous {
        lifetime time 3600 seconds;
        encryption_algorithm aes256;
        authentication_algorithm hmac_sha256;
        compression_algorithm deflate;
}
```

**关键改动**:
- `nat_traversal on` → `nat_traversal force`
- 这会强制所有流量通过UDP 4500封装，绕过ESP协议

**路由器配置**:
```
Hub地址: 112.48.19.183
协商模式: Main
NAT穿透: 启用
```

### 方案C: 使用IPSec over L2TP（最复杂）

如果方案A和B都不行，考虑使用L2TP/IPSec，它完全基于UDP。

## 🔧 推荐配置步骤

### 步骤1: 调整NAT端口映射（在NAT网关上）

**优先方案** - 使用标准端口:
```
外网端口 500  → 192.168.50.48:500
外网端口 4500 → 192.168.50.48:4500
```

**并配置协议转发**:
```
IP协议 50 (ESP) → 192.168.50.48
IP协议 47 (GRE) → 192.168.50.48
```

### 步骤2: 修改服务器Racoon配置

**当前配置可能需要调整的部分**:

```bash
# 编辑配置文件
sudo nano /etc/racoon/racoon.conf

# 确保包含NAT穿透
remote anonymous {
    nat_traversal force;  # 或 on
    ...
}
```

### 步骤3: 更新PSK密钥文件

**添加路由器的公网出口IP**:

```bash
sudo nano /etc/racoon/psk.txt

# 如果路由器从固定公网IP连接，添加该IP
# 例如路由器4G出口IP是 1.2.3.4
1.2.3.4    123456

# 如果是动态IP，保持 anonymous 模式（当前配置）
# Racoon会接受任何IP，只要PSK匹配
```

### 步骤4: 重启Racoon

```bash
sudo systemctl restart racoon

# 查看日志
sudo tail -f /var/log/syslog | grep racoon
```

### 步骤5: 配置路由器端

**路由器DMVPN配置**:
```
启用: ✓
Hub地址: 112.48.19.183  ← 公网IP
Hub端口: 500 (默认)
协商模式: Main
NAT穿透: 启用

加密算法: AES-256
认证算法: SHA-256
DH组: MODP3072 (Group 15)
PSK密钥: 123456

SA算法: AES256-SHA256
GRE密钥: 123456
GRE Hub IP: 10.0.0.1
GRE本地IP: 10.0.0.3
```

## 🐛 故障排查

### 问题1: IKE协商失败

**检查**:
```bash
# 服务器端查看日志
sudo tail -100 /var/log/syslog | grep racoon

# 常见错误
# "no response from 112.48.19.183:500"
# → NAT端口映射未生效
```

**解决**:
- 确认NAT网关500端口映射正确
- 确认防火墙允许UDP 500入站

### 问题2: Phase 1成功但Phase 2失败

**可能原因**: ESP协议被阻止

**解决**:
1. 启用NAT-T force模式
2. 确认UDP 4500映射正确
3. 检查racoon配置有 `nat_traversal force;`

### 问题3: IPSec连接成功但GRE不通

**可能原因**: GRE协议映射问题

**方案A** - 配置GRE over IPSec:
```bash
# 服务器上配置GRE隧道时指定remote为路由器的真实IP
# 这需要在IPSec连接建立后才知道路由器IP

# 或使用 "remote any" 模式
sudo ip tunnel add gre1 mode gre local 192.168.50.48 remote any key 123456
```

**方案B** - 检查NAT ALG:
```bash
# 某些NAT网关有GRE ALG（应用层网关）
# 可能需要在NAT网关上启用"GRE Passthrough"
```

### 问题4: 查看实际连接的路由器IP

```bash
# 查看IPSec SA中的对端IP
sudo setkey -D

# 输出示例:
# 192.168.50.48 <路由器真实公网IP>
#     esp mode=transport spi=...
```

## 🔑 关键要点总结

1. **端口映射必须使用标准端口** (500, 4500)
   - Racoon不支持自定义端口
   - 路由器也期望标准端口

2. **ESP和GRE是IP协议，不是端口**
   - 需要NAT网关的协议转发功能
   - 或使用 `nat_traversal force` 完全依赖UDP 4500

3. **推荐NAT-T force模式**
   - 最可靠的NAT穿透方案
   - 所有流量通过UDP 4500封装

4. **PSK可以保持anonymous模式**
   - 服务器接受任何IP的连接请求
   - 只要PSK密钥匹配即可

5. **GRE隧道配置**
   - 使用 `remote any` 模式
   - 让服务器自动学习路由器IP
