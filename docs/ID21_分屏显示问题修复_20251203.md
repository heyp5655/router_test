## 🐛 问题2: 分屏显示在烧录时中断

### 问题描述
分屏窗口显示到这里就停止了：
```
[20:51:06] 升级循环 1/1000
[20:51:06] ============================================================
[20:51:06] 步骤1: 检查串口登录状态...
[20:51:07]   ℹ️  已登录（检测到提示符）
[20:51:07] ✅ 串口已登录
[20:51:07]
[20:51:07] 步骤2: 串口烧录旧版本 32.3.0.7...
← 之后就没有任何输出了
```

### 根本原因

**问题**: `flash_old_firmware()` 方法内部使用 `print()` 输出调试信息

```python
# utils/serial_client.py
def flash_old_firmware(self, bridge_ip: str) -> bool:
    print(f"\n{'#'*70}")  # ← 输出到控制台，不是分屏窗口
    print(f"开始串口烧录旧版本固件流程 ({self.port})")
    # ...
    if not self.login():
        print(f"❌ 串口登录失败 ({self.port})")  # ← 不显示在分屏
    # ...
```

**影响**:
- `print()` 输出到主控制台（Flask服务器窗口）
- 分屏窗口通过 `log_func()` 显示，但 `flash_old_firmware()` 没有调用它
- 用户看不到烧录进度，以为程序卡死了

### 修复方案

**文件**: `test_cases/stability/multi_device_firmware_upgrade_stability_test.py`

**策略**: 在调用 `flash_old_firmware()` 前后添加进度提示，在后台线程执行烧录，主线程定期输出进度

#### 修改步骤2: 串口烧录流程（第371-415行）

```python
# === 步骤2: 串口烧录旧版本 ===
log_func(f"步骤2: 串口烧录旧版本 {self.old_version}...")

# flash_old_firmware() 内部会自动重启并烧录
# 注意：烧录后串口会断开连接，需要重新登录
log_func(f"  🔄 开始Boot模式烧录流程...")
log_func(f"     1) 重启并进入Boot模式")
log_func(f"     2) TFTP下载固件到内存 (约30-60秒)")
log_func(f"     3) 写入Flash (约60-120秒)")
log_func(f"     4) 等待系统启动 (约30-40秒)")
log_func(f"     5) 设置Bridge IP")
log_func(f"  ⏳ 预计总耗时: 约3-5分钟，请耐心等待...")
log_func("")

# 启动烧录（在后台线程中显示进度）
import threading
flash_complete = threading.Event()
flash_result = [False]  # 使用列表避免闭包问题

def flash_thread():
    try:
        result = serial_client.flash_old_firmware(bridge_ip=bridge_ip)
        flash_result[0] = result
    finally:
        flash_complete.set()

flash_worker = threading.Thread(target=flash_thread)
flash_worker.start()

# 显示进度（每30秒输出一次）
elapsed = 0
while not flash_complete.is_set():
    flash_complete.wait(timeout=30)
    if not flash_complete.is_set():
        elapsed += 30
        log_func(f"  ⏱️  烧录进行中... 已耗时 {elapsed} 秒")

# 等待线程结束
flash_worker.join(timeout=10)

if not flash_result[0]:
    raise Exception("串口烧录失败")

log_func(f"✅ 串口烧录完成")
log_func("")
```

### 工作原理

#### 1. **前置说明**
显示烧录的5个步骤和预计耗时，让用户知道在做什么：
```

   1) 重启并进入Boot模式
   2) TFTP下载固件到内存 (约30-60秒)
   3) 写入Flash (约60-120秒)
   4) 等待系统启动 (约30-40秒)
   5) 设置Bridge IP
⏳ 预计总耗时: 约3-5分钟，请耐心等待...
```

#### 2. **后台线程执行烧录**
```python
def flash_thread():
    result = serial_client.flash_old_firmware(bridge_ip=bridge_ip)
    flash_result[0] = result
    flash_complete.set()  # 完成后设置事件
```

#### 3. **主线程显示进度**

## 🎯 技术细节

### 为什么不直接修改 `flash_old_firmware()`？

**原因**:
1. **最小改动原则**: `flash_old_firmware()` 是底层工具方法，被多个地方调用
2. **职责分离**: 工具方法负责功能，测试用例负责输出
3. **避免破坏性修改**: 修改工具方法可能影响其他用例
4. **灵活性**: 不同用例可以自定义输出格式和频率

### 为什么使用后台线程？

**原因**:
1. **不阻塞主线程**: 主线程可以定期输出进度
2. **精确控制输出**: 每30秒输出一次，不受工具方法影响
3. **统一日志格式**: 所有输出都通过 `log_func()` 到分屏窗口
4. **错误隔离**: 烧录失败不会导致主线程崩溃

### 为什么使用列表存储结果？

```python
flash_result = [False]  # 使用列表

def flash_thread():
    flash_result[0] = result  # 修改列表元素
```

**原因**: Python闭包限制
- ❌ `flash_result = result` 会创建新的局部变量，外部看不到
- ✅ `flash_result[0] = result` 修改的是同一个列表对象
