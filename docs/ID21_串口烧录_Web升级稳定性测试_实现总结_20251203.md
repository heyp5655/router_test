## 🔧 技术细节

### 串口操作流程

```python
1. 打开串口
   serial = serial.Serial(port="COM7", baudrate=115200, ...)

2. 登录串口
   发送: root + 回车
   发送: R0uT3&U&s@l1nk46#3 + 回车
   等待: root@ROUTER:~#

3. 重启到Boot模式
   发送: reboot + 回车
   持续发送: q + 回车 (30秒超时)
   等待: "Enter :"
   发送: X + 回车
   等待: "please input password:"
   发送: ys23#2ls29#4 + 回车
   等待: "=>"

4. TFTP烧录
   发送: setenv ipaddr 172.168.0.10
   发送: setenv serverip 172.168.0.100
   发送: setenv imagename 32.3.0.7.ext2
   发送: run updata-image
   等待: "Loading:" 和 "#####" (上传中)
   等待: "written: OK" (烧录完成，最多5分钟)
   等待: "=>"

5. 重启设备
   发送: reset
   等待: "resetting ..."
   等待: 30秒（设备重启）

6. 烧录后登录
   重复步骤2

7. 设置Bridge IP
   发送: ifconfig Bridge0 192.168.50.18
   等待: root@ROUTER:~#
```

### Web操作流程

```python
1. 登录
   访问: http://192.168.50.18

   读取元素: //*[@id="qwert_firmware_ver"]

   重新登录

   再次检查版本号
```

## ⚠️ 注意事项

### 1. TFTP服务器

- 必须在172.168.0.100上运行TFTP服务
- 固件文件必须命名为: `32.3.0.7.ext2`
- 确保防火墙允许TFTP（UDP 69端口）

### 2. 串口占用

- 测试运行时，COM7和COM8会被独占
- 不要同时运行其他串口工具（如PuTTY）
- 异常退出后需手动重启程序释放串口

### 3. 网络配置

- 设备烧录后Bridge IP分别为192.168.50.17和192.168.50.18
- 确保PC能访问这两个IP
- 可能需要配置PC的网卡IP为192.168.50.x段

### 4. 测试时间

- 单次循环预计耗时: 约8-10分钟
  - 串口烧录: ~5分钟
  - Web升级: ~3分钟
  - 验证登录: ~1分钟

- 1000次循环预计耗时:
  - 单设备: ~5.6-6.9天
  - 双设备并行: ~5.6-6.9天（并行执行）

### 5. 错误恢复

测试具有错误恢复机制：
- 串口操作失败 → 关闭串口，继续下一次循环
- Web操作失败 → 关闭浏览器，继续下一次循环
- 失败的循环会记录在统计中

## 🐛 已知问题

1. **串口超时**: 如果设备重启时间过长，可能超过30秒超时
   - 解决：增加 `reboot_to_boot_mode()` 的超时时间

2. **TFTP上传慢**: 大固件文件可能超过5分钟
   - 解决：增加 `flash_firmware_via_tftp()` 的超时时间

3. **版本号格式**: 如果实际版本号包含前缀（如 "V32.3.0.7"）
   - 解决：修改 `check_firmware_version()` 的对比逻辑

4. **修改密码弹窗**: 如果弹窗元素定位不到
   - 解决：添加实际的Cancel按钮XPath到 `_handle_change_password_popup()`
