## 问题1: 修改用例后自动重载 ✅

### 问题描述
之前修改测试用例代码后，必须重新运行 `start_admin.bat` 才能生效。这是因为Python模块被缓存了。

### 解决方案
在 `core/test_runner.py` 中添加了模块自动重载机制：

**修改文件**: `core/test_runner.py`

1. **导入reload模块** (第1-3行):
```python
import importlib
import importlib.util
from importlib import reload
```

2. **在执行测试时自动重载** (第527-532行):
```python
# 检查模块是否已导入，如果是则重新加载
if case_info['module_path'] in sys.modules:
    self._log(f"  模块已存在，重新加载以获取最新代码...")
    module = sys.modules[case_info['module_path']]
    module = reload(module)
else:
    module = importlib.import_module(case_info['module_path'])
```

### 效果
- ✅ 修改测试用例代码后，无需重启Flask应用
- ✅ 直接在Web界面重新运行测试即可使用最新代码
- ✅ 大大提高了开发效率

## 问题2: 失败用例重测功能 ✅

### 需求描述
测试完成后，如果有用例失败，希望能单独选择失败的用例重新测试。

### 实现方案

#### 后端实现

**1. TestRunner类新增属性** (`core/test_runner.py` 第85-86行):
```python
self.last_test_request = None  # 保存最后一次测试请求
self.failed_cases = []  # 保存失败的测试用例类名列表
```

**2. 测试执行后保存失败用例** (`core/test_runner.py` 第509-522行):
```python
# 新增：保存最后一次测试请求
self.last_test_request = test_request
self._log(f"已保存最后一次测试请求配置")

# 新增：保存失败的测试用例类名
self.failed_cases = []
for result in results:
    if result['status'] in ['FAIL', 'ERROR']:
        # 找到对应的用例信息
        for case in cases_to_run:
            if case['name'] == result['test_name']:
                self.failed_cases.append(case['class_name'])
                break
self._log(f"失败用例列表: {self.failed_cases}")
```

**3. 新增方法 - 重跑失败用例** (`core/test_runner.py` 第688-744行):
```python
def rerun_failed_tests(self) -> Dict[str, Any]:
    """重新运行失败的测试用例"""
    if not self.failed_cases:
        # 返回错误提示
        ...

    # 创建新的测试请求，使用失败用例的类名
    rerun_request = TestRequest(
        router_config=self.last_test_request.router_config,
        test_mode=TestMode.SPECIFIC,
        selected_cases=self.failed_cases,  # 使用失败用例的类名
        timeout=self.last_test_request.timeout,
        restore_default=self.last_test_request.restore_default
    )

    return self.run_tests(rerun_request)
```

#### API端点

**1. 获取失败用例列表** (`app.py` 第687-724行):

**2. 重跑失败用例** (`app.py` 第727-743行):


### 使用方法
1. 运行测试，部分用例失败
2. 调用 `GET /api/failed-cases` 获取失败用例列表
3. 前端显示失败用例供用户选择（或全选）
4. 调用 `POST /api/rerun-failed` 重新运行失败的用例

## 问题3: 快速重跑上次测试 ✅

### 需求描述
测试完成后，希望能一键重复上次的测试配置，快速重跑整个测试。

### 实现方案

#### 后端实现

**新增方法 - 重跑上次测试** (`core/test_runner.py` 第746-775行):
```python
def rerun_last_test(self) -> Dict[str, Any]:
    """重新运行上次的测试（完整重跑）"""
    if not self.last_test_request:
        # 返回错误提示
        ...

    self._log(f"重新运行上次测试")
    self._log(f"测试模式: {self.last_test_request.test_mode.value}")
    self._log(f"选中的用例: {self.last_test_request.selected_cases}")

    return self.run_tests(self.last_test_request)
```

#### API端点

**重跑上次测试** (`app.py` 第746-762行):
```python
@app.route('/api/rerun-last', methods=['POST'])
def rerun_last_test():
    """重新运行上次的测试（完整重跑）"""
    result = test_runner.rerun_last_test()
    return jsonify(result)
```

### 使用方法
1. 运行任意测试
2. 测试完成后，调用 `POST /api/rerun-last`
3. 系统将使用上次的完整配置重新运行所有测试

## API端点总结

| 端点 | 方法 | 功能 | 参数 |
|------|------|------|------|
| `/api/failed-cases` | GET | 获取失败用例列表 | 无 |
| `/api/rerun-failed` | POST | 重跑失败用例 | 无（使用保存的配置） |
| `/api/rerun-last` | POST | 重跑上次测试 | 无（使用保存的配置） |

## 注意事项

1. **模块重载限制**:
   - 只重载测试用例模块
   - 如果修改了 `core/` 或 `utils/` 下的代码，仍需重启Flask应用

2. **失败用例保存**:
   - 失败用例列表在每次测试完成后更新
   - 重跑失败用例后，列表会根据最新结果更新

3. **测试配置保存**:
   - 只保存最后一次测试的配置
   - 包括路由器配置、测试模式、选中的用例等完整信息

4. **并发测试**:
   - 当前不支持并发测试
   - 如果测试正在运行，应禁用重跑按钮
