**创建日期**: 2025-12-15

**测试项**: 稳定性
**测试点**: web固定两版本循环升级稳定性验证

## 📋 需求概述

根据用例步骤.xlsx中的ID 41，实现一个在两个固件版本之间通过Web反复升级的稳定性测试，循环100次，并检测上传失败情况。

### 原始需求

- **测试项**: 稳定性
- **测试点**: web固定两版本循环升级稳定性验证
- **步骤**:
  1. 登录到路由器，跳转到升级页面（设备默认使用https登录，会响应比较慢需要增长一点响应时间）
  2. 上传升级文件，点击升级
  3. 等待上传文件完成，同时判断页面的 `<span class="ys-upload-error">Importing firmware. Please stay on this page till upgrade is finished.</span>` 里面有没有打印"Failed to upload. Please try again"
  4. 如果有则记录次数证明上传文件失败，如果没有则证明上传成功继续点击升级并进入下一轮循环
  5. 循环100次

4. **统计功能**

   - 升级失败次数（版本号未更新）
   - 成功率和失败率
   - 失败循环编号和详情

**检测流程**:

   - 检查 `<span class="ys-upload-error">` 元素
   - 如果包含"Failed to upload. Please try again"，返回上传失败
   - 如果出现确认对话框，上传成功
   - 超时600秒（10分钟）

## 📊 测试流程

### 完整测试步骤

1. **Setup阶段**:
   - 检查版本A固件文件 (35.3.0.10.bin)
   - 检查版本B固件文件 (35.3.0.11-a1.bin)
   - 创建路由器客户端（增加HTTPS超时）
   - 登录路由器
   - 检查当前版本，确定初始升级方向

2. **Execute阶段** (循环100次):
   - 确定目标版本（A或B交替）
   - Web上传并升级固件
   - 检测上传失败提示
   - 等待路由器重启（120秒）
   - 重新登录路由器
   - 验证版本号
   - 输出进度统计（成功率、平均耗时、预计完成时间）

3. **Cleanup阶段**:
   - 关闭路由器客户端
   - 输出最终统计报告

### 失败处理策略

- **上传失败**: 记录失败次数，下次重试相同版本
- **升级失败**: 记录失败次数，尝试重新登录，继续下一轮
- **登录失败**: 尝试重新登录，如果仍然失败则跳过此轮
