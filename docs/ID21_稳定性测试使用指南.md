## ⏱️ 预计耗时

**假设每次升级需要2.5分钟**:

| 循环次数 | 每台设备耗时 | 两台串行耗时 |
|---------|------------|------------|
| 10次    | ~50分钟    | ~1.7小时   |
| 100次   | ~8.3小时   | ~16.7小时  |
| 1000次  | ~83小时    | ~167小时(7天) |

**建议**:
1. 先运行10次测试验证功能
2. 再运行100次测试评估稳定性
3. 最后运行完整的1000次测试

## ❌ 常见问题

### 1. 固件文件未找到

```
❌ 固件文件不存在: E:\GIT\ROUTER_TEST\docs\upload\new\...
```

**解决方案**:
- 确认固件文件已放入对应目录
- 检查文件扩展名是否正确
- 确保文件名中没有特殊字符

### 2. 设备无法登录

```
❌ 设备1登录失败
```

**解决方案**:
- 检查路由器IP是否正确
- 确认用户名密码（admin/admin1）
- 检查网络连通性: `ping 192.168.50.17`
- 确认路由器Web界面可以通过浏览器访问

### 3. 升级超时

```
❌ 升级超时（已等待 300 秒）
   路由器可能未成功重启或网络不可达
```

**解决方案**:
- 确认固件文件是否正确
- 检查固件文件是否损坏
- 适当延长超时时间（修改测试用例中的 `upgrade_timeout`）
- 手动登录路由器检查升级状态

### 4. 部分循环失败

```
设备1 - 循环 245 失败（旧版本升级失败）
```

**原因**:
- 网络短暂中断
- 路由器重启时间较长
- 固件升级过程异常

**处理方式**:
- 测试会自动继续下一个循环
- 最终报告会显示失败循环编号
- 可根据失败率判断稳定性

## 🛑 中断测试

如需中断正在运行的测试：

1. **Web界面**: 关闭浏览器标签页或刷新页面
2. **命令行**: 按 `Ctrl + C` 强制中断

**注意**: 中断后需手动关闭可能残留的Chrome浏览器进程。
