# SSH启用自动检查功能实现

**实现日期**: 2025-12-12
**问题背景**: 新版本路由器固件默认关闭SSH功能，导致所有需要SSH连接的测试用例失败
**解决方案**: 在所有使用SSH的测试用例中添加自动检查和启用SSH的功能

---

## 一、问题描述

### 症状
从日志 `logs/test_run_20251212_153927.log` 中发现，所有使用SSH的测试用例都失败了：

```
SFTP上传脚本失败: timed out
TimeoutError: timed out
正在SSH连接到路由器 192.168.3.1 (使用root用户)...
```

### 根本原因
新版本路由器固件默认关闭SSH功能，导致：
1. SSH端口22无法连接
2. 无法上传测试脚本
3. 无法执行远程命令
4. 所有依赖SSH的测试用例失败

---

## 二、解决方案

### 2.1 核心实现

在 `core/router_client.py` 中添加 `ensure_ssh_enabled()` 方法：

**文件**: `core/router_client.py:5761-5837`

**功能**:
1. 跳转到防火墙Security页面 (`#network/firewall/security`)
2. 刷新页面获取最新状态
3. 检查SSH复选框状态 (`//*[@id="1_ssh_local"]`)
4. 如果未启用，自动勾选并保存应用
5. 再次验证SSH是否已成功启用

**关键代码**:
```python
def ensure_ssh_enabled(self) -> bool:
    """
    确保SSH功能已启用

    新版本路由器固件默认关闭SSH，需要通过Web界面主动开启。
    此方法会检查SSH是否启用，如果未启用则自动启用并保存。

    Returns:
        bool: SSH启用成功返回True，失败返回False
    """
```

### 2.2 测试用例更新

在所有使用SSH的测试用例的 `setup()` 方法中添加SSH启用检查：

```python
# 检查并启用SSH（新版本固件默认关闭SSH）
print("前置条件: 检查SSH启用状态...")
if not self.router_client.ensure_ssh_enabled():
    raise Exception("SSH未启用且自动启用失败，无法继续测试")
print("✅ SSH已就绪\n")
```

## 六、注意事项

### 6.1 兼容性
- ✅ 向下兼容：如果SSH已启用，方法直接返回成功，不重复操作
- ✅ 向上兼容：新固件版本默认关闭SSH也能自动启用

### 6.2 安全性
- ⚠️ 此功能会自动修改路由器配置（启用SSH）
- ⚠️ 测试完成后不会自动关闭SSH（避免影响后续测试）
- ⚠️ 建议在测试环境使用，生产环境需谨慎

### 6.3 失败处理
如果SSH启用失败，测试用例会：
1. 抛出异常：`Exception: SSH未启用且自动启用失败，无法继续测试`
2. 终止测试执行
3. 记录详细错误日志

## 七、后续优化建议

### 7.1 可选优化
1. **测试清理阶段恢复SSH状态**
   - 在 cleanup() 中记录SSH初始状态

2. **配置化SSH启用**
   - 在配置文件中添加 `auto_enable_ssh` 选项
   - 允许用户选择是否自动启用SSH

3. **SSH状态缓存**
   - 首次检查后缓存SSH状态
   - 避免每个测试用例都重复检查
