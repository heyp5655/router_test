# 多进程文件上传冲突修复

**修复时间**: 2025-12-02 20:30
**问题**: 两个进程同时打开文件选择对话框，路径重复输入到同一个弹窗
**解决方案**: 使用进程锁（multiprocessing.Lock）串行化文件上传操作

---

## 问题分析

### 用户观察
> "我看两个路径全部输入到了一个弹窗里面"

### 问题现象

**截图显示**：
```
文件名(N): E:\GIT\ROUTER_TEST\docs\upload\old\32.3.0.7.bin\E:\GIT\ROUTER_TEST\...\32.3.0.7.bin
错误提示: 文件名无效
```

**根本原因**：
1. **进程1** 打开文件选择对话框 → pyautogui粘贴路径
2. **进程2** 同时打开文件选择对话框 → pyautogui也粘贴路径
3. 因为 `pyautogui` 操作的是**全局键盘和鼠标**
4. 两个进程的 `Ctrl+V` 都粘贴到了**同一个对话框**
5. 结果：路径被粘贴**两次**，变成无效路径

### 为什么会这样？

**pyautogui的工作原理**：
```python
# 进程1
pyautogui.hotkey('ctrl', 'v')  # 操作全局键盘

# 进程2（同时运行）
pyautogui.hotkey('ctrl', 'v')  # 也操作全局键盘
```

**问题**：
- pyautogui **不知道**是哪个进程在调用
- 键盘事件发送到**当前活动窗口**（可能是任何一个对话框）
- 如果两个对话框都打开，后打开的通常是活动窗口
- 两个进程的粘贴操作都作用在**同一个窗口**

---

## 解决方案：进程锁

### 核心思想

使用 `multiprocessing.Lock` 确保**同一时间只有一个进程**执行文件上传操作。

### 实现代码

```python
from multiprocessing import Lock

# 1. 创建全局锁
file_upload_lock = Lock()

# 2. 在文件上传时使用锁
def _upgrade_firmware_in_process(..., upload_lock: Lock):
    with upload_lock:
        print(f"[{device_name}] 🔒 获得文件上传锁，开始上传...")
        success = device_client.upload_and_upgrade_firmware(...)
        print(f"[{device_name}] 🔓 释放文件上传锁")
    return success
```

### 工作流程

**修复前（并行，会冲突）**：
```
时间线：
0s  |  进程1: 打开对话框
0s  |  进程2: 打开对话框
1s  |  进程1: Ctrl+V (粘贴到对话框2)  ❌
1s  |  进程2: Ctrl+V (粘贴到对话框2)  ❌
2s  |  对话框2: 路径重复，无效！
```

**修复后（串行，不冲突）**：
```
时间线：
0s  |  进程1: 🔒 获得锁 → 打开对话框 → Ctrl+V → Enter → 上传 → 🔓 释放锁
30s |  进程2: ⏸️ 等待锁...
30s |  进程2: 🔒 获得锁 → 打开对话框 → Ctrl+V → Enter → 上传 → 🔓 释放锁
```

## 修改的代码

### 1. 导入Lock
```python
from multiprocessing import Process, Queue, Lock
```

### 2. 创建全局锁
```python
# 全局文件上传锁（确保同一时间只有一个进程上传文件）
file_upload_lock = Lock()
```

### 3. 修改函数签名
```python
def _test_device_in_process(..., upload_lock: Lock):
    # 函数体

def _upgrade_firmware_in_process(..., upload_lock: Lock):
    with upload_lock:
        # 文件上传操作
```

### 4. 传递锁给子进程
```python
upload_lock = Lock()

process1 = Process(
    target=_test_device_in_process,
    args=(..., upload_lock)  # 传递锁
)

process2 = Process(
    target=_test_device_in_process,
    args=(..., upload_lock)  # 传递锁
)
```

## 为什么不完全并行？

### 技术限制

| 方案 | 优点 | 缺点 | 可行性 |
|------|------|------|--------|
| pyautogui | 简单易用 | 全局键鼠，不支持并行 | ✅ 当前方案 |
| JavaScript | 速度快 | 部分网站不支持 | ✅ 已实现（优先） |
| HTTP API | 完美并行 | 需要路由器支持 | ❌ 路由器不支持 |
| 多虚拟桌面 | 真正并行 | 实现复杂 | ❌ 暂不考虑 |

### 当前最优方案

**双保险策略** + **进程锁**：

1. **优先使用JavaScript**（绕过对话框，不受锁影响）
2. **备用pyautogui**（有锁保护，串行但可靠）
3. **结果**：大部分情况用JavaScript并行，少数情况用pyautogui串行
