# ID15 数据对比问题修复

**修复时间**: 2025-11-27
**问题**: IPv6和Connection Duration对比失败，但实际值是正确的

---

## 问题描述

运行测试时发现两个字段对比失败：

### 问题1: IPv6对比失败
```
✗ IPv6 不一致
  MQTT: fe80::b437:e4ff:fe7a:7c7/64
  页面: fe80::b437:e4ff:fe7a:7c7/64 (处理后: fe80::b437:e4ff:fe7a:7c7)
```

**原因**:
- 原代码只处理页面值的`/64`前缀长度
- 但MQTT返回的IPv6地址也包含`/64`
- 导致对比时MQTT值仍带`/64`，而页面值已去掉，造成不匹配

### 问题2: Connection Duration对比失败
```
✗ Connection Duration 不一致
  MQTT: 0 days, 11:52:03
  页面: 0 days, 11:51:52
```

**原因**:
- 两个时间相差11秒
- 这是获取页面数据和MQTT响应之间的正常时间延迟
- 原代码使用精确字符串匹配，无法容忍这种正常的时间差

---

## 修复方案

### 修复1: IPv6前缀长度处理

**文件**: `test_cases/mqtt_test/mqtt_cellular_status_report_test.py`
**方法**: `verify_network_data()` (约720-728行)

**修改前**:
```python
# 特殊处理IPv6（页面格式: fe80::xxx/64, MQTT格式: fe80::xxx）
if mqtt_field == 'ipv6' and '/' in page_value:
    page_value = page_value.split('/')[0]
```

**问题**: 假设MQTT值不带前缀长度，只处理页面值

**修改后**:
```python
# 特殊处理IPv6（MQTT和页面都可能包含前缀长度，统一去掉再对比）
if mqtt_field == 'ipv6':
    # MQTT可能是 "fe80::xxx/64" 或 "fe80::xxx"
    # 页面可能是 "fe80::xxx/64" 或 "fe80::xxx"
    # 统一处理：去掉前缀长度再对比
    if '/' in mqtt_value:
        mqtt_value = mqtt_value.split('/')[0]
    if '/' in page_value:
        page_value = page_value.split('/')[0]
```

**优势**:
- ✅ 同时处理MQTT和页面的前缀长度
- ✅ 适应两种格式（带/不带前缀长度）
- ✅ 对比更健壮，不受格式影响

#### 2.2 添加辅助方法 (约789-837行)

```python
def _is_time_similar(self, mqtt_time, page_time, tolerance_seconds=60):
    """比较两个时间字符串是否相似（允许一定时间差）

    Args:
        mqtt_time: MQTT时间字符串，格式: "0 days, 11:52:03"
        page_time: 页面时间字符串，格式: "0 days, 11:51:52"
        tolerance_seconds: 允许的时间差（秒），默认60秒

    Returns:
        bool: 时间差在允许范围内返回True，否则返回False
    """
    try:
        # 解析时间字符串
        def parse_duration(time_str):
            """解析时间字符串为总秒数"""
            # 格式: "0 days, 11:52:03" 或 "1 days, 01:23:45"
            parts = time_str.strip().split(',')
            if len(parts) != 2:
                return None

            days_str = parts[0].strip().split()[0]  # "0 days" -> "0"
            time_str = parts[1].strip()  # "11:52:03"

            days = int(days_str)
            time_parts = time_str.split(':')
            if len(time_parts) != 3:
                return None

            hours, minutes, seconds = map(int, time_parts)
            total_seconds = days * 86400 + hours * 3600 + minutes * 60 + seconds
            return total_seconds

        mqtt_seconds = parse_duration(mqtt_time)
        page_seconds = parse_duration(page_time)

        if mqtt_seconds is None or page_seconds is None:
            # 无法解析，使用精确匹配
            return mqtt_time.lower() == page_time.lower()

        # 计算时间差的绝对值
        time_diff = abs(mqtt_seconds - page_seconds)

        # 判断是否在允许范围内
        return time_diff <= tolerance_seconds

    except Exception as e:
        # 解析失败，使用精确匹配
        print(f"      ⚠️  时间解析失败: {e}，使用精确匹配")
        return mqtt_time.lower() == page_time.lower()
```

**功能说明**:
1. 解析时间字符串为总秒数
2. 计算两个时间的差值（绝对值）
3. 判断差值是否 ≤ 60秒
4. 如果解析失败，回退到精确字符串匹配

**时间容差**: 默认60秒
- 获取页面数据：约3秒
- 发送MQTT请求：约1秒
- 接收MQTT响应：约1秒
- 路由器处理时间：约1秒
- 总延迟：约6-10秒，60秒容差足够宽松
