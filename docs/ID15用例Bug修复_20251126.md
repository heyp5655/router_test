## 🐛 发现的Bug

### Bug 1: MQTT服务器地址格式错误 ❌

**问题描述**:
```python
# 错误代码
if not self.router_client.input_text('//*[@id="1_m_server_addr"]',
                                     f"{self.mqtt_broker}:{self.mqtt_port}"):
```

**问题分析**:
- 代码将IP地址和端口合并成 `192.168.50.36:1883` 格式填入服务器地址字段
- 实际上路由器页面的服务器地址字段应该只填写IP地址
- 端口应该在单独的端口字段填写（如果有的话）

**影响**:
- 路由器无法正确解析服务器地址
- MQTT连接会失败

---

### Bug 2: 保存后未点击应用按钮 ❌

**问题描述**:
```python
# 步骤12: 点击应用按钮
print("  步骤12: 应用配置")
# 这里使用router_client的通用方法，不需要手动点击应用按钮  ← 错误注释！

# 步骤13: 等待MQTT连接建立
```

**问题分析**:
- 注释说"不需要手动点击应用按钮"是错误的
- 保存配置后，路由器需要点击应用按钮才会真正应用配置
- 直接等待MQTT连接会超时失败，因为配置还没有应用

**影响**:
- MQTT配置不会生效
- 连接状态检查会超时
- 测试会失败

---

## ✅ 修复方案

### 修复 Bug 1: 正确填写服务器地址

**修复代码**:
```python
# 步骤5: 填写服务器地址（只填写IP，不包含端口）
print(f"  步骤5: 填写服务器地址 {self.mqtt_broker}")
if not self.router_client.input_text('//*[@id="1_m_server_addr"]', self.mqtt_broker):
    print("  ⚠️  输入服务器地址失败")
    return False
```

**修复说明**:
- 移除端口号拼接，只填写 IP 地址
- 更新日志输出，去除端口显示
- 如果路由器页面有单独的端口字段，端口会在默认值中自动使用（通常是1883）

**文件位置**: `test_cases/mqtt_test/mqtt_cellular_status_report_test.py:178-182`

### 修复 Bug 2: 添加应用按钮点击逻辑

**修复代码**:
```python
# 步骤12: 点击应用按钮
print("  步骤12: 点击应用按钮")
# 尝试多个可能的应用按钮选择器
apply_selectors = [
    '//*[@id="apply"]',
    '//button[contains(@id, "apply")]',
    '//*[contains(text(), "应用")]',
    '//*[contains(text(), "Apply")]',
    '//*[@id="mqtt_list"]//button[contains(text(), "Apply") or contains(text(), "应用")]'
]

apply_clicked = False
for selector in apply_selectors:
    try:
        if self.router_client.click_element(selector):
            print(f"  ✅ 成功点击应用按钮")
            apply_clicked = True
            break
    except:
        continue

if not apply_clicked:
    print("  ⚠️  未找到应用按钮或点击失败，继续等待MQTT连接...")

time.sleep(3)
```

**修复说明**:
1. **多选择器策略**: 定义5个可能的应用按钮选择器
   - 按ID查找：`//*[@id="apply"]`
   - 按ID包含查找：`//button[contains(@id, "apply")]`
   - 按文本查找（中文）：`//*[contains(text(), "应用")]`
   - 按文本查找（英文）：`//*[contains(text(), "Apply")]`
   - 在MQTT列表中查找：`//*[@id="mqtt_list"]//button[...]`

2. **容错处理**:
   - 遍历所有选择器，找到第一个可点击的按钮
   - 如果都失败，不中断测试，继续等待连接（可能页面自动应用）
   - 输出警告信息提示未找到应用按钮

3. **等待时间**: 点击应用后等待3秒，让路由器处理配置

**文件位置**: `test_cases/mqtt_test/mqtt_cellular_status_report_test.py:222-246`

## 💡 经验总结

### 1. Web自动化测试的常见问题
- **元素定位**: 页面可能有多种布局，需要多个选择器
- **等待时间**: 保存、应用等操作后需要适当等待
- **容错处理**: 关键步骤要有降级方案

### 2. 字段格式问题
- **不要假设格式**: 要查看实际页面的字段要求
- **分离IP和端口**: 很多系统将IP和端口分开填写
- **验证输入**: 填写后要验证是否正确显示

### 3. 按钮查找策略
- **多种定位方式**: ID、类名、文本内容、XPath
- **中英文双语**: 支持中英文界面
- **层级定位**: 在特定容器内查找（避免误点击其他页面的按钮）
