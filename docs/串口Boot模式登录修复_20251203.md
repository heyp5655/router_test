## 修复方案

### 修改文件
- `utils/serial_client.py` - `reboot_to_boot_mode()` 方法

### 核心修改

#### **修改前** (错误 - 提前盲目发送):
```python
# 步骤2: 持续发送'q'
while time.time() - start_time < 30:
    self.serial.write(b'q\r\n')  # ❌ 在倒计时出现之前就发送
    time.sleep(0.3)

    if "Enter :" in output:      # ⚠️ 可能检测到错误的提示
        entered_boot = True
        break
```

#### **修改后** (正确 - 等待倒计时再发送):
```python
# 步骤2: 等待U-Boot倒计时提示
found, output = self.read_until("Hit any key to stop autoboot", timeout=30)
if not found:
    return False

# 步骤3: 检测到倒计时后，立即发送'q'进入User Menu
time.sleep(0.3)  # 短暂延迟确保倒计时显示完成
self.send_command("q", wait_time=1)

# 步骤4: 等待User Menu提示 "Enter :"
found, output = self.read_until("Enter :", timeout=10)
if not found:
    return False

# 步骤5: 发送'X'
self.serial.write(b'X\r\n')

# 步骤6: 等待密码提示
found, output = self.read_until("please input password:", timeout=10)

# 步骤7: 输入密码
self.send_command(self.boot_password, wait_time=2)

# 步骤8: 验证Boot模式 (=> 提示符)
found, output = self.read_until(self.boot_prompt, timeout=10)
```

## 技术细节

### 1. 关键时机控制

**问题**：原代码在设备reboot后立即开始发送'q'，但此时：
- U-Boot还没启动
- 倒计时还没显示
- 'q'被忽略或作为无效输入

**解决**：使用 `read_until()` 等待 "Hit any key to stop autoboot" 出现
- 确保在正确的时机发送'q'
- 避免盲目发送导致的失败

### 2. User Menu vs 正常启动

| 场景 | 提示符 | 如何进入 |
|------|--------|---------|
| **User Menu** | `Enter :` | 在倒计时时按'q' + Enter |
| **正常启动** | `root@ROUTER:~#` | 倒计时结束，自动启动 |

如果'q'发送时机不对，设备会正常启动进入系统，而不是User Menu。

### 3. 时序优化

- 检测倒计时: 30秒超时（足够长，覆盖设备启动时间）
- 发送'q'延迟: 0.3秒（确保倒计时显示完成）
- 等待User Menu: 10秒超时（User Menu出现很快）
- 发送'X'延迟: 0.5秒（确保提示符稳定）
