## 🔍 升级失败判断机制

### 判断流程概览

```
upload_and_upgrade_firmware() 方法返回:
  ├─ True  → 升级成功 ✅
  └─ False → 升级失败 ❌

测试用例根据返回值判断:
  ├─ success = True  → stats["success"] += 1
  └─ success = False → stats["failed"] += 1
                       stats["failed_cycles"].append(cycle)
```

### 2. TestCase._upgrade_firmware() - 处理升级结果

**文件**: `test_cases/stability/multi_device_firmware_upgrade_stability_test.py`
**方法**: `_upgrade_firmware()`
**位置**: 第352-375行

```python
def _upgrade_firmware(self, device_client, firmware_path, device_name, cycle, firmware_type):
    """执行单次固件升级"""
    try:
        # 调用RouterClient的升级方法
        success = device_client.upload_and_upgrade_firmware(
            firmware_path=firmware_path,
            timeout=self.upgrade_timeout  # 默认300秒
        )

        if success:
            # ✅ 升级成功
            self.log_info(f"  [{device_name}] ✅ {firmware_type}升级成功")
            return True
        else:
            # ❌ 升级失败（RouterClient返回False）
            self.log_error(f"  [{device_name}] ❌ {firmware_type}升级失败")
            return False

    except Exception as e:
        # ❌ 异常失败（调用过程中出现异常）
        self.log_error(f"  [{device_name}] ❌ {firmware_type}升级异常: {e}")
        traceback.print_exc()
        return False
```

### 3. TestCase._test_device() - 统计失败

**文件**: `test_cases/stability/multi_device_firmware_upgrade_stability_test.py`
**方法**: `_test_device()`
**位置**: 第300-350行

```python
def _test_device(self, device_client, device_name, new_firmware, old_firmware, stats):
    """测试单个设备的固件升级循环"""

    for cycle in range(1, self.upgrade_cycles + 1):
        # 第一步：升级到旧版本
        success = self._upgrade_firmware(
            device_client, old_firmware, device_name, cycle, "旧版本"
        )

        if not success:
            # ❌ 旧版本升级失败
            stats["failed"] += 1  # 失败次数+1
            stats["failed_cycles"].append(cycle)  # 记录失败的循环号
            self.log_error(f"[{device_name}] ❌ 循环 {cycle} 失败（旧版本升级失败）")
            continue  # 跳过本次循环，进入下一次

        stats["success"] += 1  # 成功次数+1

        # 第二步：升级到新版本
        success = self._upgrade_firmware(
            device_client, new_firmware, device_name, cycle, "新版本"
        )

        if not success:
            # ❌ 新版本升级失败
            stats["failed"] += 1  # 失败次数+1
            stats["failed_cycles"].append(cycle)  # 记录失败的循环号
            self.log_error(f"[{device_name}] ❌ 循环 {cycle} 失败（新版本升级失败）")
            continue  # 跳过本次循环，进入下一次

        stats["success"] += 1  # 成功次数+1
        stats["total"] = cycle  # 记录完成的循环数
```

## 🎯 判断标准总结

### 成功的标准（唯一）

**必须满足所有条件**:
1. ✅ 文件成功上传（等待300秒完成）
2. ✅ 点击升级按钮成功
3. ✅ 路由器接收固件并开始升级
4. ✅ 路由器成功重启
5. ✅ **能够重新登录路由器**（最关键！）

**判断依据**: `login_web_force()` 返回 `True`

### 失败的标准（多种）

**任何一个条件不满足都算失败**:
1. ❌ 固件文件不存在
2. ❌ 无法找到上传输入框/升级按钮
3. ❌ 点击按钮失败
4. ❌ 路由器未响应/未重启
5. ❌ **无法重新登录路由器**（最常见！）
6. ❌ 超时（300秒内无法登录）
7. ❌ 任何异常（浏览器崩溃等）

**判断依据**:
- `login_web_force()` 返回 `False`
- 或抛出任何异常

## 📊 失败检测的关键点

### 1. 重新登录是核心判断

**为什么用"能否重新登录"判断升级成功？**

```
升级流程:
  1. 上传固件文件
  2. 点击升级按钮
  3. 路由器接收文件
  4. 路由器验证固件
  5. 路由器刷写固件
  6. 路由器重启系统
  7. 路由器启动完成
  8. Web服务启动
  9. 能够重新登录 ← 此时确认升级完成！
```

**只有能重新登录，才能证明**:
- ✅ 路由器成功刷写了固件
- ✅ 路由器成功重启了
- ✅ 新固件能正常运行
- ✅ Web服务正常工作

**如果无法登录，可能是**:
- ❌ 固件损坏，刷写失败
- ❌ 路由器卡在启动过程
- ❌ 新固件有bug，无法启动Web服务
- ❌ 网络不可达

### 2. 超时机制

**默认超时**: 300秒（5分钟）

**超时计算**:
```python
# 第2704行
max_retries = (timeout - wait_time) // 10
# timeout = 300秒（总超时）
# wait_time = 60秒（初始等待路由器重启）
# max_retries = (300 - 60) // 10 = 24次

# 总等待时间：
# 60秒（初始等待）+ 24次 × 10秒 = 300秒
```

**每10秒重试一次登录**:
- 尝试1次: 70秒
- 尝试2次: 80秒
- ...
- 尝试24次: 300秒
- 超过300秒 → 判定失败

### 3. 异常捕获

**两层异常捕获**:

**第一层** (第2712-2721行): 单次登录异常
```python
try:
    if self.login_web_force(max_retries=1):
        return True  # 成功
except Exception as e:
    print(f"   登录失败: {e}")
    # 不返回，继续下一次重试
```

**第二层** (第2732-2736行): 整个升级流程异常
```python
try:
    # 整个升级流程（步骤1-9）
    ...
except Exception as e:
    print(f"\n❌ 升级过程中出错: {e}")
    return False  # 失败
```

## 🔧 可能的失败场景

### 场景1: 登录超时（最常见）

**现象**:
```
步骤9: 尝试重新登录路由器...
  尝试第 1/24 次登录（已等待 70 秒）...
  登录失败: ...
  尝试第 2/24 次登录（已等待 80 秒）...
  登录失败: ...
  ...
  尝试第 24/24 次登录（已等待 300 秒）...
  登录失败: ...

❌ 升级超时（已等待 300 秒）
   路由器可能未成功重启或网络不可达
```

**可能原因**:
- 路由器固件刷写失败，卡住
- 路由器启动过程太慢（>5分钟）
- 网络断开
- 路由器IP地址改变

### 场景2: 文件上传前失败

**现象**:
```
步骤2: 查找文件上传输入框...
  ❌ 无法找到文件上传输入框

❌ 升级过程中出错: ...
```

**可能原因**:
- 页面加载失败
- 页面结构改变
- 浏览器问题

### 场景3: 点击按钮失败

**现象**:
```
步骤5: 点击升级按钮...
  ❌ 点击升级按钮失败: ...

❌ 升级过程中出错: ...
```

**可能原因**:
- 按钮被遮挡
- 按钮状态为disabled
- JavaScript错误

### 场景4: 浏览器崩溃

**现象**:
```
步骤6: 等待文件上传到路由器...
  ⏳ 上传中... 还需等待约 3 分 0 秒
  [Chrome崩溃]

❌ 升级过程中出错: ...
```

**可能原因**:
- 内存不足
- Chrome bug
- 文件过大

## 💡 改进建议

### 当前判断方式的优缺点

**优点**:
- ✅ 简单明确：能登录 = 成功
- ✅ 可靠：登录成功证明路由器正常工作
- ✅ 无需额外验证：不需要检查固件版本

**缺点**:
- ❌ 无法区分失败原因（上传失败 vs 刷写失败 vs 重启失败）
- ❌ 超时时间固定，可能不够灵活
- ❌ 无法判断固件是否真的升级成功（可能重启后仍是旧版本）

### 可能的改进方向

#### 1. 增加固件版本验证

```python
# 登录成功后，验证固件版本
if self.login_web_force(max_retries=1):
    # 读取固件版本
    actual_version = self.get_firmware_version()
    expected_version = self.parse_firmware_version(firmware_path)

    if actual_version == expected_version:
        print(f"✅ 固件版本验证成功: {actual_version}")
        return True
    else:
        print(f"❌ 固件版本不匹配: 期望{expected_version}, 实际{actual_version}")
        return False
```

#### 2. 增加失败原因分类

```python
class UpgradeResult:
    success: bool
    error_type: str  # "timeout", "upload_failed", "button_click_failed", etc.
    error_message: str
    elapsed_time: int

# 返回详细结果
return UpgradeResult(
    success=False,
    error_type="login_timeout",
    error_message="无法在300秒内重新登录",
    elapsed_time=300
)
```

#### 3. 动态超时时间

```python
# 根据固件大小调整超时
firmware_size_mb = os.path.getsize(firmware_path) / (1024 * 1024)
if firmware_size_mb > 50:
    timeout = 600  # 大固件增加到10分钟
else:
    timeout = 300  # 小固件5分钟
```

## 📌 总结

### 判断升级失败的核心逻辑

**唯一成功标准**: 能够在超时时间内（300秒）重新登录路由器

**失败判断**:
1. 超时无法登录 → 返回 `False`
2. 升级过程异常 → 返回 `False`
3. 调用过程异常 → 返回 `False`

**关键方法**:
- `RouterClient.upload_and_upgrade_firmware()` - 执行升级，返回布尔值
- `TestCase._upgrade_firmware()` - 处理返回值
- `TestCase._test_device()` - 统计失败次数和循环号

**核心思想**: 重新登录成功 = 升级成功，因为这证明了路由器成功刷写固件、重启并正常运行。
