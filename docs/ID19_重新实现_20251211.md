## 问题分析

### 原实现的问题
原来的实现将测试逻辑封装在 `router_client.test_cross_page_port_conflict_openvpn_firewall()` 方法中，虽然功能完整，但存在以下问题：
1. 测试流程不够清晰直观
2. 难以调试和维护
3. 与其他端口冲突测试的风格不一致

### 用例步骤要求
根据 `用例步骤.xlsx` 中的ID19定义：
```
步骤1：去防火墙界面配置ftp端口为1111（配置方法参照用例：设备防火墙界面检查静态端口冲突）
       这里要区别是只配置ftp端口配置完后要先启用ftp勾选然后保存并点击应用

步骤2：去openvpn界面配置端口为1111（配置方法参照用例：设备open vpn界面端口冲突）
       这里需要弹窗提醒才算通过
```

## 新实现方案

### 设计原则
1. **直接在测试用例中实现**：不再调用router_client的封装方法
2. **严格按照用例步骤**：明确分为两大步骤，每步有清晰的子步骤
3. **参考ID12和ID18**：保持代码风格一致
4. **详细的日志输出**：便于调试和问题定位

### 测试流程

#### 步骤1：防火墙界面配置FTP端口并应用
```
1.1 跳转到防火墙Security页面 (#network/firewall/security)
1.2 配置FTP端口为 1111
1.3 启用FTP功能 (勾选 FTP Local)
1.4 保存并应用配置
    - 点击保存按钮
    - 处理可能的确认弹窗
    - 点击应用按钮
    - 等待应用完成弹窗
```

#### 步骤2：OpenVPN界面配置端口并检测冲突
```
2.1 跳转到OpenVPN服务器页面 (#vpn/openvpn/server)
2.2 启用OpenVPN服务器
2.3 配置OpenVPN端口为 1111
2.4 点击保存按钮
2.5 检测端口冲突弹窗（关键步骤）
    - 等待弹窗出现（3秒超时）
    - 获取弹窗内容
    - 点击OK关闭弹窗
    - 有弹窗 = ✅ 测试通过
    - 无弹窗 = ❌ 测试失败
```

### 关键技术点

#### 1. 页面导航路径
- **防火墙Security**: `#network/firewall/security`
- **OpenVPN服务器**: `#vpn/openvpn/server` （注意不是 `#network/vpn/server`）

#### 2. 元素定位

#### 3. 配置备份恢复
```python
def setup(self):
    # 备份防火墙Security配置（只备份FTP端口）
    self.firewall_config = self.router_client.backup_firewall_security_config()

    # 备份OpenVPN配置
    self.openvpn_config = self.router_client.backup_openvpn_config()

def cleanup(self):
    # 先恢复OpenVPN配置
    self.router_client.restore_openvpn_config(self.openvpn_config)

    # 再恢复防火墙配置
    self.router_client.restore_firewall_security_config(self.firewall_config)
```
