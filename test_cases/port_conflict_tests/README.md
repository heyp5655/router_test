## ✅ 项目中的两个端口冲突检测测试用例

### 1️⃣ ID11 - 端口映射全端口扫描测试

**文件**: `test_cases/port_conflict_tests/port_conflict_detection_test.py`

**测试名称**: 端口冲突检测测试（全端口扫描）

**测试对象**: 防火墙端口映射（Port Mapping）功能

**测试内容**:
- 在端口映射添加规则时，测试**所有端口（1-65535）**
- 验证保留端口列表的完整性和准确性

**测试逻辑**:
- ✅ **保留端口** → 应该**有弹窗**（冲突提示）
- ✅ **非保留端口** → 应该**无弹窗**（可以正常添加）

**保留端口列表**（13个）:
```
22, 53, 1701, 9001, 68, 500, 4500, 123, 1, 58, 7574, 9993, 520
```

**测试范围**: 全端口扫描（1-65535，共65535个端口）

**预计耗时**: 约6-9小时

**状态**: ✅ 已实现，未修改

### 2️⃣ ID12 - 防火墙Security端口冲突检测测试

**文件**: `test_cases/port_conflict_tests/firewall_security_port_conflict_test.py`

**测试名称**: 设备防火墙配置静态端口冲突

**测试对象**: 防火墙Security页面的5个端口字段

**测试内容**:
- 测试HTTP、HTTPS、TELNET、SSH、FTP端口字段
- 验证这些字段的端口冲突检测功能是否生效

**测试逻辑**:
- ✅ **所有保留端口** → 都应该**有弹窗**（冲突检测生效）
- ❌ **如果无弹窗** → 测试失败（冲突检测失效）

**测试字段**（5个）:
```
1. HTTP端口    (//*[@id="1_http_port"])
2. HTTPS端口   (//*[@id="1_https_port"])
3. TELNET端口  (//*[@id="1_telnet_port"])
4. SSH端口     (//*[@id="1_ssh_port"])
5. FTP端口     (//*[@id="1_ftp_port"])
```

**测试范围**: 仅保留端口（13个端口 × 5个字段 = 65次测试）

**预计耗时**: 约5.6分钟

**参考实现**: `D:\WK\Milesight\AUTO\port_check.py` 的 `configure_firewall_Security_ports()`

**状态**: ✅ 已正确实现
